# Cardano Island — Time Axis Design Spec

**Date:** 2026-10-20
**Status:** Approved in conversation; the user asked for an autonomous build.
**Builds on:** `2026-10-20-cardano-island-design.md`

## 1. Purpose

Add history to the island. A visitor scrubs or plays a monthly timeline and watches the ecosystem evolve:

- Ships arrive when their transactions start, sail away when transactions stop, and come back when activity resumes.
- A deterministic stream of settlers carries each ship's activity from its harbor along its dependency chains up to the Cardano mark.
- Roads wear according to monthly transaction volume.
- Buildings are founded, grow, burn, fall into ruin and return to grass as their use and maintenance come and go.

## 2. Decisions

| Topic | Decision |
|---|---|
| Granularity | Monthly, from **2021-09** (Alonzo, the start of smart contracts) to the current month. |
| Usage metric | Transactions per month. A customer's flow is `weight = log10(1 + tx)`. |
| Road wear | Monthly transitive traffic using these weights (the existing algorithm, run per month). |
| Decay | Counted in **inactive months** = months since the later of the last commit and the last traffic month. Burning at ≥ 4, ruin at ≥ 6, grass (gone) at ≥ 12. |
| At risk | Traffic continues, but there have been no commits for ≥ 6 months. A distinct "cracked, scaffolded" look, not decay. |
| Closed source | No repository → only usage counts towards decay. Never at risk. |
| No chain data | Dated presence (`active.from` / `active.until`) with a fixed small flow equivalent to 10 tx/month, marked as coming from announcements. |
| Where it runs | Activity is collected into committed JSON (`data/activity/`). The pipeline computes the timeline at build time, and the page only reads `world.json`. |

## 3. Data

### 3.1 YAML additions (all optional)

On nodes and customers:

```yaml
onchain:
  scripts: [<script hash hex>, …]      # Plutus/native script hashes whose executions count as this entity's transactions
  metadataLabels: [<int>, …]           # transaction metadata labels (notary / supply-chain products)
  addresses: [<bech32 address>, …]     # issuer addresses (organizations)
  source: https://…                    # where the identifiers came from (registry, plutus.json, docs)
active:
  from: 2023-05                        # YYYY-MM, first month of announced activity
  until: 2025-01                       # YYYY-MM, optional last month
```

### 3.2 Activity files (generated by `npm run collect:activity`, committed)

- `data/activity/tx/<id>.json`: `{ "id", "source", "query", "collected": "YYYY-MM-DD", "months": { "YYYY-MM": count } }`
- `data/activity/commits/<id>.json`: `{ "id", "repo", "collected", "months": { "YYYY-MM": count } }`

Months with zero activity may be omitted. The data loader treats `data/activity/` as an allowed folder.

**Sources:**
- **Transactions:** the Yaci Store MCP (`https://yaci-playground.cf-app.org/mcp`), tool `analytics-execute-sql` (DuckDB):
  - scripts → `transaction_scripts`, counting distinct `tx_hash` per month;
  - labels → `transaction_metadata`;
  - addresses → `address_utxo` by `owner_addr`.
- **Commits:** the GitHub GraphQL API, `history(since, until).totalCount` on the default branch, one aliased field per month. Uses `GITHUB_TOKEN` or the `gh` CLI token.

## 4. Computation (pipeline, `pipeline/timeline.ts`)

Months `M = [2021-09 … current]`.

**Product transactions per month:** `tx_p(m)` from the activity file.

**Customer flow `tx_c(m)`**, from the first rule that applies:
1. The customer's own activity file, if it exists.
2. `active` dates, if set: 10 inside the window, otherwise 0.
3. If `type: segment`: the sum of `tx_p(m)` over the products it uses that have activity.
4. Otherwise: 10 in months where any product it uses has `tx_p(m) > 0`, otherwise 0.

A customer with `stage: ended` and no data at all has flow 0 throughout.

**Weights:** `w_c(m) = log10(1 + tx_c(m))`.

**Traffic:** `traffic(m)` uses the same closure walk as `computeTraffic`, with `w_c(m)` as the weight and only non-inferred edges.

**Usage of a node in month m:** `traffic_n(m) > 0`, or its own `tx_n(m) > 0`.

**Founded:** the first month with a commit, usage, or `active.from`. If none exists, the node counts as founded at the start, for pre-2021 projects without data.

**Node state per month, in order:**
1. Before founding → `empty`.
2. `inactive = m − max(lastCommit ≤ m, lastUse ≤ m)` in months. For nodes without a repo, only `lastUse` counts.
   - When the node has never been used or committed to since founding, inactivity counts from the founding month.
3. `inactive ≥ 12` → `grass`; `≥ 6` → `ruin`; `≥ 4` → `burning`.
4. The founding month itself → `construction`.
5. Used this month through traffic but without own transactions, has a repo, and `m − lastCommit ≥ 6` → `at-risk`. A product busy with its own transactions is evidently operated, even when its public repository is quiet.
6. Otherwise → `active`.

Nodes **without any activity data at all** (no repo and no transactions) stay `active` throughout and are marked "no activity data". Without evidence, the timeline must not ruin them.

**Tier per month:** quartiles of that month's node traffic, computed as in `flags.ts`.

**Ship state per month:**
- `docked` when `w_c` is above zero in `m` or either of the two months before it. A ship only sails away after three quiet months, so sparse actors such as a treasury don't shuttle back and forth.
- `wreck` when `stage: ended` and the flow is 0 after a period of activity.
- `away` otherwise.

The renderer interpolates between months.

### 4.1 `world.json` additions

```ts
timeline: {
  months: string[],                         // "2021-09" … current
  totals: number[],                         // ecosystem tx per month (sparkline)
  customers: Record<id, { w: number[]; tx: number[]; state: string /* one char per month: d docked, a away, w wreck */ }>,
  nodes: Record<id, { traffic: number[]; tier: string /* digits 0-4, 0 = not standing */; state: string /* one char per month */; commits: number[]; tx: number[]; lastCommit: string | null; lastUse: string | null; noData: boolean }>,
  edges: number[][],                        // traffic per month, aligned with world.edges order
}
```

State characters: `e` empty, `c` construction, `a` active, `r` at-risk, `b` burning, `u` ruin, `g` grass.

The current-month values remain the defaults of the existing fields, so the map without the timeline still works.

## 5. Renderer

- **Time `T`:** a continuous value measured in months (index into `months` plus a fraction). Everything visible is a pure function of `T` and the wall-clock animation time (only for decorative motion). Scrubbing to the same `T` always shows the same buildings, ships and settler positions.
- **Timeline bar:**
  - slider, play/pause, 1×/4×, "Now";
  - a sparkline of `totals`, the current month label, and the stats for that month;
  - keyboard: arrows step one month;
  - defaults to now.
- **Buildings:**
  - built once; state layers are toggled per month;
  - `empty` and `grass` → hidden, plot outline with grass tufts;
  - `construction` → scaffolding around a half-height building;
  - `burning` → animated flames and smoke;
  - `ruin` → the existing ruin look;
  - `at-risk` → cracks, darker tint, scaffolding on one side;
  - the tier scale animates between months.
- **Roads:** tile traffic for month `T` is the sum of the edge traffic crossing the tile. The surface uses thresholds rescaled for log weights. Roads whose two ends are not standing are hidden.
- **Ships:**
  - docked at the berth;
  - leave by moving seaward over the transition month and fading;
  - return in reverse;
  - wrecks near the harbor.
- **Settlers:** each docked customer emits `ceil(w_c · k)` settlers (global cap ≈ 400). Each follows a fixed route: harbor → each product it uses → the product's heaviest dependency chain → the core district → the mountain trail → the Cardano mark. The position is a pure function of (settler index, `T`, wall-clock seconds).
- **Panel:** a sparkline (tx for ships and products, commits for projects), "last commit" and "last on-chain activity", a sentence explaining the state at `T`, and the data sources.
- **Lenses:** stranded and hidden highways are evaluated at month `T`, using that month's traffic.

## 6. Testing

- **Unit:**
  - flow rules 1–4;
  - weights;
  - per-month traffic;
  - the state machine at each boundary (3/4/5/6/11/12 months, recovery, at-risk, no repo, no data, construction);
  - ship states;
  - tier per month;
  - collector query builders and response parsers;
  - the settler route builder;
  - the timeline interpolation helpers.
- **e2e:** the slider moves to a past month, the label changes, and a building's panel reports the state for that month.

## 7. Out of scope

- Per-edge start dates; an edge exists whenever both ends are standing.
- Sub-monthly resolution.
- Live data in the browser.
